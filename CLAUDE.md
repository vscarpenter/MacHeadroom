# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Mac Headroom is a sandboxed, Mac App Store-targeted macOS menu bar app
(SwiftUI `MenuBarExtra`, macOS 14+, Swift 6 strict concurrency, zero
dependencies, no network) that shows top-10 CPU and memory consumers,
collapsing every process that belongs to one app into a single row. The
original build brief is `claude-code-prompt-menu-bar-monitor.md`; the
sandbox constraints and why memory means resident size (not
`phys_footprint`) are documented with evidence in `SANDBOX_NOTES.md`.

## Build and test

```bash
xcodebuild -project MacHeadroom.xcodeproj -scheme MacHeadroom -configuration Debug build
xcodebuild test -project MacHeadroom.xcodeproj -scheme MacHeadroom -configuration Debug -destination 'platform=macOS,arch=arm64'
# One suite:
xcodebuild test ... -only-testing:MacHeadroomTests/GroupingEngineTests
```

- Tests are hosted inside the app (`TEST_HOST`), so `xcodebuild test`
  needs the destination, not just a build, and test code runs inside the
  real sandboxed app process — sampler tests exercise the real syscalls.
- The app and test targets must be signed with the same development
  team (`DEVELOPMENT_TEAM` in the pbxproj, both targets). If the test
  bundle fails to load with "different Team IDs", the signing drifted.
- Version numbers live in `Configuration/Shared.xcconfig`
  (`MARKETING_VERSION`, `CURRENT_PROJECT_VERSION`); the About tab and a
  test read them from the bundle, so a release bump is one edit there.

### Adding files

The Xcode project uses classic PBXGroup groups, NOT synchronized
folders. Every new source file needs four `project.pbxproj` edits:
PBXBuildFile entry, PBXFileReference entry, the owning group's
`children`, and the target's Sources build phase. Follow the existing
hand-rolled ID scheme (`E1…/E2…` test files, `H1…/H2…` UI files, etc.).

## Architecture

Data flows one way, with purity boundaries that make the interesting
logic fixture-testable:

- `Sampling/` reads the process table (`sysctl KERN_PROC_ALL` +
  `proc_pidinfo`) and computes CPU percent from deltas between ticks.
  `SamplerService` (actor) owns all mutable sampling state — and owns
  the clock: tick timestamps are taken inside the actor, next to the
  sweep. Never pass a caller-captured timestamp in; a timestamp captured
  before an actor hop goes stale under contention, and dividing a
  sweep's CPU accrual by a near-zero wall time once inflated CPU
  percentages a thousandfold (`SamplerBurstTests` guards this).
- `Grouping/` is pure — no syscalls, no AppKit. `GroupingEngine`
  resolves each process to an app via parent-pid ancestry, then
  " Helper" name-stripping, then standalone fallback.
- `App/MonitorStore.swift` (`@MainActor @Observable`) bridges sampler
  to UI: runs the timer, pulls `NSWorkspace` metadata, publishes the
  top-10 lists. Sampling runs only while the popover is open or the
  menu-bar-text option is on; Swift property observers don't fire in
  `init`, so launch-time behavior that depends on a stored preference
  must be triggered explicitly there.
- `App/SingleInstanceGuard.swift`: every launch broadcasts a takeover
  notice over `DistributedNotificationCenter`; older instances quit, so
  the newest launch always wins. Practical effect: to redeploy a new
  build, just build and `open` it — no pkill or scripted quit needed.
- `UI/` is the popover, settings (tabbed: General + About), the process
  glossary, and the menu bar glyph.

## Hard-won constraints (violating these reintroduces fixed bugs)

- **Popover ideal height must not depend on list content.**
  `MenuBarExtra(.window)` sizes its panel once, at open, before the
  first sample lands, and never grows it. The list region has a fixed
  height for this reason; `PopoverLayoutTests` asserts the invariant
  (equal intrinsic height, empty vs populated store).
- **Process names are truncated to 16 characters** (`kinfo_proc.p_comm`,
  `MAXCOMLEN`). `ProcessGlossary` stores and looks up keys in truncated
  form; any name-matching logic must account for this.
- **Sandbox boundaries** (measured, see SANDBOX_NOTES.md): same-user
  processes expose CPU ticks and resident size via `proc_pidinfo`;
  `proc_pid_rusage`/`phys_footprint` is EPERM for non-self; root and
  other-user processes are invisible. Don't "fix" the memory metric to
  match Activity Monitor — that decision is documented and settled.
- **Branding**: "Mac" and "Headroom" always typeset with equal size,
  weight, and color. The standard appearance uses no character imagery,
  glitch motifs, or shutter shades. The user-enabled Max Headroom mode
  may use the approved original synthetic-host cameo, restrained scanlines,
  and shutter geometry; telemetry itself must remain undistorted. The menu
  bar glyph and app icon are generated by committed scripts in `Design/`
  (do not hand-edit the PDFs/PNGs; edit the script and re-run).
- **Termination is capability-gated.** The App Sandbox denies every way
  to quit or kill another process (measured July 26, 2026; see the
  SANDBOX_NOTES.md addendum). Quit UI must stay behind
  `MonitorStore.canTerminate` and only the unsandboxed Direct build
  (`Scripts/build-direct.sh`) has it. Do not add termination UI to the
  Mac App Store build.
- **Port enumeration is sysctl-only.** Under the App Sandbox,
  `proc_pidinfo(PROC_PIDLISTFDS)` is EPERM for every non-self process
  and `bind()` is EPERM outright, so ports come from
  `net.inet.{tcp,udp}.pcblist_n` — hand-copied xnu layouts in
  `PortTableABI.h`, which MUST stay inside `#pragma pack(4)` and whose
  entries emit INPCB-first — and the live test's oracle is netstat, not
  a self-bound listener. Measured Aug 1, 2026; see the SANDBOX_NOTES.md
  ports addendum before "fixing" any of this.

## Verifying UI changes on this machine

This dev environment has no Screen Recording or Accessibility
permission: no screenshots, no synthetic clicks. What works:

- `lsappinfo info -only pid "Mac Headroom"` and `ps` for liveness;
  `/usr/bin/log show --info --debug --predicate 'process == "Mac Headroom"'`
  for the unified log (plain `log` is shadowed by a zsh builtin).
- To exercise the sampling loop headless, direct-exec the binary from
  the shell (sandbox still applies; env vars inherit). `print()` output
  is block-buffered when redirected — quit the app gracefully via
  AppleScript so stdio flushes; `kill` drops it.
- `defaults write com.vinnycarpenter.MacHeadroom …` from the shell hits
  `~/Library/Preferences`, which the sandboxed app never reads; its real
  prefs are in `~/Library/Containers/com.vinnycarpenter.MacHeadroom/`.
- Final visual confirmation is Vinny's — ask rather than guess. A newly
  launched menu bar icon can land in Control Center's hidden overflow
  area on a crowded menu bar (README documents this gotcha).
